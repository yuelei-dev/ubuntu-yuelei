# 黄雀 AI 编导一键出片与智能包装系统设计

## 1. 目标

建设一套面向竖屏知识口播和产品讲解的自动视频生产工作台。用户输入完整文案并选择数字人、声音和模板后，系统自动完成编导拆镜、数字人口播、素材检索或生成、字幕对齐、Remotion 包装、FFmpeg 压制和质量检查，输出可发布的视频。

数字人是混合成片中的固定 A-Roll，主要承担开场、自我介绍、观点阐述、段落过渡和结尾号召；产品图、实拍、AI 图片、图生视频、图表和截图作为 B-Roll。系统既要通过固定形象建立 IP，又要避免全程数字人口播造成画面单调。

## 2. 第一阶段范围

### 2.1 必须实现

- 输入完整文案并选择数字人、声音、时长和模板。
- AI 自动拆分数字人、图片、视频、图表和截图镜头。
- 接入一个数字人服务、一个文生图服务和一个图生视频服务。
- 支持用户上传素材、企业素材库检索和静态图片推拉动画。
- 生成逐字字幕并自动突出关键词。
- 提供七种基础 Remotion 镜头布局和一种竖屏知识口播主题。
- 使用异步任务队列执行生成、转码、渲染和检测。
- 支持单镜头编辑、锁定、重新生成和版本回退。
- 输出 720P 预览及 1080×1920 正式视频。
- 使用 FFmpeg 完成媒体标准化、响度统一和最终压制。
- 对素材缺失、黑帧、静音、字幕越界和时长异常进行基础检查。

### 2.2 暂不实现

- 类似剪映的自由拖拽时间轴。
- 多人数字人对话与实时直播数字人。
- AI 完全自由设计版式。
- 大规模素材交易市场。
- 手机端复杂编辑。
- 同时接入大量数字人及视频模型。
- 自动发布到社交平台。

## 3. 用户模式

系统提供三种执行模式：

- 全自动：输入后直接生成最终视频。
- 审核分镜：编导完成后暂停，确认后继续。
- 审核成片：自动生成低清预览，确认后输出高清版本。此模式为默认值。

入口支持快速模式和专业模式。快速模式输入完整文案、数字人、声音、时长和模板；专业模式允许修改分镜类型、提示词、素材、字幕和布局。

## 4. 总体架构与数据流

系统按逻辑划分为 API、编导、素材生成、数字人、时间轴、渲染和质量检测模块。第一阶段采用模块化单体，不预先拆成微服务；生成与渲染通过异步队列隔离。

主流程：

1. 接收文案与项目配置。
2. 编导生成结构化分镜。
3. 并行生成数字人、检索或生成素材、生成或识别音频与字幕。
4. 标准化所有媒体文件。
5. 根据精确音频时长重新计算时间轴。
6. Remotion 按模板组装画面、字幕和包装。
7. FFmpeg 完成混音、压制和封面处理。
8. 质量检测通过后发布结果；失败时只重试相关镜头。

## 5. 编导模块

### 5.1 职责

编导模块负责：

- 文案断句和语义分段。
- 判断每段表达目的和镜头类型。
- 生成素材检索词和生成提示词。
- 估算镜头时长。
- 标记标题、字幕重点和关键词。
- 选择布局、转场和包装主题。
- 校验视频节奏及数字人占比。

### 5.2 默认决策规则

- 自我介绍、人物身份、观点、态度、总结和行动号召使用数字人。
- 段落之间的承上启下默认使用数字人。
- 产品外观和使用过程使用图片、实拍或图生视频。
- 数据及对比关系使用图表或对比布局。
- 证书、报告和聊天记录仅使用用户上传或可验证素材。
- 抽象概念使用图片、短视频或文字卡片。
- 数字人连续出镜不超过 12 秒。
- 单个素材镜头通常为 3 至 6 秒。
- 每个镜头只承担一个主要表达任务。
- 开场 3 秒内必须出现人物、结果或冲突之一。
- 每 10 至 15 秒至少发生一次明显视觉变化。
- 用户上传素材优先于素材库，素材库优先于 AI 生成。
- 数字人建议占总时长的 30% 至 50%。

### 5.3 分镜协议

项目级数据包含标题、画幅、分辨率、帧率、目标时长、语言、风格、数字人、声音和模板。镜头级数据示例：

```json
{
  "id": "scene_003",
  "order": 3,
  "type": "avatar",
  "purpose": "transition",
  "script": "第一个特点，就是使用非常简单。",
  "durationEstimate": 4.2,
  "visual": {
    "layout": "avatar_with_title",
    "headline": "特点一",
    "highlightWords": ["使用简单"],
    "cameraMotion": "none",
    "transitionIn": "cut",
    "transitionOut": "zoom"
  },
  "audio": {
    "source": "tts",
    "emotion": "confident",
    "speed": 1.0
  },
  "asset": null
}
```

允许的镜头类型包括 `avatar`、`image`、`image_video`、`stock_video`、`upload`、`chart`、`screenshot` 和 `text_fallback`。

## 6. 素材与数字人生成

### 6.1 获取优先级

素材按照以下顺序获取：

1. 用户上传素材。
2. 企业素材库。
3. 获得授权的版权素材库。
4. AI 文生图。
5. AI 图生视频。
6. 默认文字或品牌背景模板。

涉及产品外观、证书、新闻和具体数据时，禁止使用不准确的 AI 结果替代；无法获取真实素材时进入 `NEEDS_USER_INPUT`，或在不影响事实表达时降级为明确的文字卡片。

### 6.2 数字人生成

数字人镜头接收数字人 ID、声音 ID、文本和情绪。每段前后保留约 0.2 至 0.4 秒自然余量，避免剪辑截断动作。多个相邻数字人镜头可合并请求，但输出必须能依据时间戳切回分镜。

### 6.3 缓存

素材缓存键由模型版本、提示词、尺寸、时长和参考素材哈希组成。相同输入复用结果。每次重新生成保存新版本，不立即覆盖旧结果。

### 6.4 失败降级

- 图生视频失败：生成图片加 Remotion 推拉动画，再降级为相近版权素材或品牌文字卡片。
- 数字人失败：重试一次，再使用备用供应商；若仍失败，使用静态人物图加轻微动画并明确标记需要审核。
- 素材检索失败：尝试文生图，再使用通用相关素材或文字卡片。
- 单个失败不重新执行已成功的镜头。

## 7. Remotion 模板系统

### 7.1 分层

模板分为项目组合、镜头布局、公共包装组件和品牌主题。模板不得写死具体标题、人物或素材，只消费分镜协议。

### 7.2 第一阶段布局

- `AvatarFullScene`：数字人全屏。
- `AvatarTitleScene`：数字人加顶部观点标题。
- `AvatarPipScene`：素材为主，数字人小窗。
- `VisualFullScene`：图片或视频全屏。
- `VisualCardScene`：模糊背景加中央素材卡片。
- `ComparisonScene`：左右或上下对比。
- `TextFallbackScene`：素材失败后的文字动效。

公共组件包含字幕、标题、媒体容器、Logo、安全区域、进度标识、转场、音乐和音效。

### 7.3 推荐目录

```text
src/
├── compositions/
├── scenes/
├── components/
├── themes/
├── timeline/
└── schemas/
```

### 7.4 时间轴

编导输出预计时长，最终时长以生成或上传音频为准：

```text
durationInFrames = ceil(audioDurationSeconds × fps)
startFrame = 前面所有镜头帧数之和
```

转场在相邻镜头内部占用 6 至 12 帧，不额外改变总音频时长。所有字幕使用相对镜头的毫秒时间戳，并在构建时间轴时转换为全局帧。

### 7.5 字幕与安全区

1080×1920 输出采用以下默认约束：

- 顶部标题区域：纵坐标 140 至 380。
- 主体视觉区域：纵坐标 300 至 1450。
- 字幕区域：纵坐标 1320 至 1640。
- 底部平台遮挡区域：纵坐标 1700 至 1920。
- 左右边距至少 60 像素。
- 每行建议不超过 14 至 16 个中文字符，最多两行。
- 当前词、编导关键词和普通字幕采用不同层级，避免同时使用多种抢眼动画。

第一阶段为每个数字人配置固定安全字幕位置，不进行逐帧人体检测。

### 7.6 主题

字体、字号、颜色、阴影、安全区、标题动画、字幕动画和转场时长均由主题配置控制。更换风格只切换主题和布局组合，不修改分镜数据。

## 8. FFmpeg 媒体处理

FFmpeg 负责：

- 视频转码、裁切、补帧和色彩空间统一。
- 音频提取、响度统一和多轨混音。
- 最终 H.264/AAC 压制。
- 封面和必要元数据处理。

Remotion 负责画面布局和动画；FFmpeg 不重复实现组件级视觉逻辑。

## 9. API 与任务状态

### 9.1 创建项目

`POST /api/projects` 接收输入文案、数字人、声音、输出规格和自动化选项，立即返回 `projectId` 与 `jobId`。

### 9.2 状态机

```text
CREATED
→ SCRIPTING
→ STORYBOARDING
→ WAITING_FOR_ASSETS
→ GENERATING_ASSETS / GENERATING_AVATAR
→ ALIGNING_TIMELINE
→ RENDERING
→ QUALITY_CHECK
→ COMPLETED
```

异常状态包括 `RETRYING`、`PARTIALLY_FAILED`、`NEEDS_USER_INPUT`、`FAILED` 和 `CANCELLED`。

### 9.3 核心接口

- `GET /api/projects/{id}`：查询项目、进度和镜头状态。
- `POST /api/projects/{id}/storyboard/regenerate`：重新编导。
- `PATCH /api/projects/{id}/scenes/{sceneId}`：修改镜头。
- `POST /api/projects/{id}/scenes/{sceneId}/regenerate`：局部重新生成。
- `POST /api/projects/{id}/render`：触发预览或正式渲染。
- `POST /api/projects/{id}/cancel`：取消未完成任务。
- `GET /api/projects/{id}/output`：获取结果和历史版本。

## 10. 队列、并发和幂等

第一阶段使用 TypeScript、BullMQ 和 Redis。任务类型包括：

- `script.generate`
- `storyboard.generate`
- `asset.search`
- `image.generate`
- `video.generate`
- `avatar.generate`
- `audio.transcribe`
- `timeline.align`
- `remotion.render`
- `ffmpeg.encode`
- `quality.inspect`

数字人、图片、视频、检索和语音识别任务在分镜确认后并行执行。每个供应商设置独立并发和速率限制。

任务幂等键为 `projectId + sceneId + taskType + inputHash`。网络错误重试三次，限流使用指数退避，内容审核失败不重复提交相同输入，质量重生成最多两次，确定性参数错误直接失败或等待用户输入。

## 11. 存储

媒体文件进入对象存储：

```text
projects/{projectId}/
├── input/
├── storyboard/storyboard.json
├── audio/
├── scenes/{sceneId}/
├── renders/
└── reports/quality.json
```

数据库保存项目、用户、分镜、文件地址、任务状态、版本、模型参数、提示词、费用、耗时和错误记录，不保存视频二进制。

## 12. 工作台

第一阶段包含：

1. 创建项目：输入文案并选择数字人、声音、时长及模板。
2. 编导分镜：按顺序展示镜头卡片，允许修改、切换类型、锁定和重新生成。
3. 素材中心：查看候选、上传、替换、回退和失败原因。
4. 视频预览：播放完整时间轴，定位镜头，修改字幕、标题和素材裁切。
5. 导出记录：下载视频、封面、字幕、分镜 JSON 和历史版本，查看时间及费用。

第一阶段不建设自由时间轴编辑器。

## 13. 质量检查

渲染前检查：

- 镜头时长、主要音频和素材是否存在。
- 布局、字体和主题是否合法。
- 视频是否短于目标镜头。
- 图片能否在安全区合理裁切。
- 所有镜头帧数之和是否等于项目总帧数。

渲染后检查：

- 输出是否为 1080×1920、H.264、AAC。
- 音画总时长误差是否不超过约 100 毫秒。
- 是否存在黑帧、冻结、无故静音或损坏。
- 字幕是否越过安全区域。
- 数字人和素材是否按分镜正确交替。
- 用户真实素材是否被错误替换。

## 14. 性能和可观察性

- 60 秒视频低清预览目标在 10 分钟内完成，外部模型排队时间单独统计。
- 不含外部模型等待时，Remotion 渲染目标为 2 分钟以内。
- 第一阶段至少支持 5 个项目并发排队。
- 每个项目记录各模型耗时、费用、重试次数和失败原因。
- 前端使用 SSE 或 WebSocket 展示进度，轮询作为兜底；外部系统可订阅 Webhook。

## 15. 验收标准

- 输入完整文案并选择数字人后，无需人工操作即可输出视频。
- 数字人和 B-Roll 能按编导分镜正确交替。
- 单镜头失败不会使整个项目从头开始。
- 失败任务能够降级、重试或明确请求用户素材。
- 用户可单独修改和重新生成镜头，并锁定其他镜头。
- 输出字幕不越界，无黑帧和异常静音。
- 相同输入可以命中缓存并复用结果。
- 所有任务均可查询状态，并保留版本、费用和错误记录。

## 16. 推荐技术基线

- 应用及 API：TypeScript。
- 模板渲染：Remotion。
- 媒体处理：FFmpeg。
- 队列：BullMQ 与 Redis。
- 数据库：PostgreSQL。
- 对象存储：S3 兼容存储。
- 字幕：带逐字时间戳的内部 JSON，导出时支持 SRT/ASS。
- 数字人、文生图和图生视频通过供应商适配器接入，业务层不依赖具体厂商字段。
