# 提示词反推生成视频：可选形象与时长设计

## 目标

在编导页的“提示词反推”结果中，用户点击“一键生成视频”后，先选择是否使用人物形象，并选择 5、10 或 15 秒成片时长。

- 选择形象：使用现有电影化身能力生成视频。
- 不选择形象：保持现有果肉剧情视频链路。
- 两条链路都使用用户选择的时长。
- 不改变提示词反推本身每条链接 20 点的价格。

## 用户流程

1. 用户完成提示词反推。
2. 用户点击“一键生成视频”。
3. 页面打开选择窗口，加载当前用户已有形象。
4. 用户单选一个形象，或选择“不使用形象”。
5. 用户选择成片时长：5、10 或 15 秒。
6. 窗口实时显示视频费用：
   - 5 秒：150 点
   - 10 秒：300 点
   - 15 秒：450 点
7. 用户确认后提交任务；默认选择“不使用形象”和 10 秒。

如果用户没有已有形象，窗口显示“还没有形象”和“去创建形象”入口，但不阻止选择“不使用形象”继续生成。

## 技术方案

### 前端

改动 `site/workbench/script.html`，复用页面已有的形象选择窗口及 `/api/gen/video/avatars` 数据源。反推模式的“一键生成视频”不再立即调用 `_doGenerate`，而是先打开新的可选形象/时长窗口。

窗口输出统一的选择结果：

```text
avatar_id: 形象 ID 或 null
duration: 5 | 10 | 15
```

选择形象时，前端调用现有 `/api/gen/cinematic`：

```json
{
  "cine_mode": "open",
  "avatar_ids": [42],
  "prompt": "反推提示词",
  "duration": 10,
  "ratio": "9:16",
  "resolution": "720p",
  "enhance_prompt": false
}
```

不选择形象时，前端继续调用 `/api/gen/script_to_video`：

```json
{
  "style": "剧情",
  "scenes": [{"scene": "反推提示词", "line": "", "dur": "10s"}],
  "duration": 10
}
```

两条任务都沿用现有 job 轮询和完成/失败展示，不新建生成接口。

### 后端

不增加新的业务接口，不修改电影化身和果肉视频引擎。

- `/api/gen/cinematic` 继续负责形象归属校验、动态计费、电影化身队列、失败退款和资产保存。
- `/api/gen/script_to_video` 继续负责无形象的剧情视频；现有 `duration` 参数直接传入果肉视频。
- 反推任务与视频任务分别计费，反推的 20 点不包含视频费用。

## 状态与错误处理

- 形象加载中：窗口显示加载状态，确认按钮不可提交“使用形象”的任务。
- 形象加载失败：显示重试提示，同时保留“不使用形象”选项。
- 形象在提交前被删除：由电影化身接口的归属校验拒绝，并显示现有错误信息。
- 点数不足：显示所需点数和充值入口。
- 任务生成失败：沿用标准 job 失败和退款提示。
- 用户关闭窗口：不提交任务、不扣点。
- 防重复提交：确认后锁定按钮，收到任务 ID 或明确失败后再恢复。

## 安全与计费边界

- 前端传入的形象 ID 不可信，最终以现有 `/api/gen/cinematic` 服务端归属校验为准。
- 视频费用必须由后端现有 `cost_of` 逻辑计算，前端的 150/300/450 仅用于展示。
- 不复制或下放任何供应商密钥。
- 不修改数据库结构、点数单价、视频引擎或主服务器配置。

## 测试

前端回归测试覆盖：

- 反推生成按钮会先打开选择窗口。
- 默认“不使用形象 + 10 秒”。
- 5/10/15 秒显示正确费用。
- 不选形象提交 `script_to_video` 且透传所选时长。
- 选择形象提交 `cinematic`，包含正确的 `avatar_ids`、提示词和时长。
- 无形象、加载失败、关闭窗口不会错误提交。
- 确认按钮防止重复提交。

后端现有测试继续证明：

- `script_to_video` 剧情链路按传入时长生成果肉视频。
- `cinematic` 校验形象归属并按秒计费。
- 两类任务失败时按标准任务生命周期退款。

## 不在本次范围

- 在选择窗口内创建新形象。
- 多选形象。
- 添加参考图片或参考视频。
- 自动润色反推提示词。
- 修改反推、果肉视频或电影化身价格。
- 修改视频页现有电影化身面板。
