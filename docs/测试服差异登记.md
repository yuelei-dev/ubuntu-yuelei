## 四、漂移监控

- 哨兵：`/home/ubuntu/hq-drift/drift_sentinel.py`，比对 yuelei 镜像的 `origin/baseline/test-server`（= tang@54c4d2b 快照；**ref 已从 tang main 切换**）
- 例外机制：已上线。**仅巡检路径生效；`--verify-deploy` 完全绕开例外、严格比对 运行文件 == git ref**。例外条目 = `path + drift_kind + 指纹`（`sha256` 运行时内容哈希 / `ref` 等于某**不可变提交**（完整 40 位 SHA；schema 拒绝分支名/tag/短 SHA，移动 ref 会造成假阴性）版本 / `absent` 仅用于 missing）；drift_kind 与指纹完全匹配才进 `registered` 桶（"已登记例外 N 处"）。**漂移桶之外独立遍历清单全部条目核对当前实际状态**：命中但 kind/指纹不符、恢复基线内容、missing 被补上、added 被删除，一律进 `exceptions_stale` 并给出偏离说明；**stale-only（无普通漂移）同样返回非零并告警**，登记保留的功能被回退/删除不会静默漏报
- 已部署 test-runtime overlay 的权威期望记录在 `/home/ubuntu/hq-drift/active_overlays.json`，记录只保存 manifest 路径和完整部署 SHA；常规巡检每次从该不可变提交重新校验 manifest 与 postimage SHA-256，并以 postimage 原子取代相同路径的旧 preimage 例外。合法部署不会产生 `exceptions_stale`，任意单字节偏移仍进真实漂移；活动清单损坏或提交不可读时巡检 fail-closed
- 清单 `deploy/test-server-exceptions.json`（schema_version 1，严格校验；配置错误 → 告警"按零例外巡检"并继续，绝不崩溃）。**读取顺序：env `HQ_DRIFT_EXCEPTIONS`（本地文件）→ `git show <HQ_DRIFT_EXCEPTIONS_REF 或 GIT_REF>:deploy/test-server-exceptions.json`**
- 对账数字（对 baseline/test-server，共 **58** 处）：changed 47 = 滞留旧版 37 + yuelei 版本 6 + PR171 覆盖层 1 + 版本绑定部署 3（PR #174：jobs_store.py / imggen_api.py / leadgen_api.py，ref 型例外锁定 yuelei main 精确提交 `f03cab377875a2d47a9566bd51ccfccff5f29be8`；**这三个文件再次部署后指纹即失效，需重新登记**）；missing 10（absent 型）；added 1。其中 55 处逐文件归属见 `docs/测试服漂移清单-20260803.md`，版本绑定 3 处为清单生成后 PR #174 部署新增——58 处全部已登记为例外并带指纹
- **例外清单落地（两步）**：①清单随哨兵 PR 合并进 yuelei `main`；②**通过独立 PR（base = `baseline/test-server`）把清单提交进 baseline 分支**——该分支更新同样必须走完整 PR 门禁（评审 + CI + 合并提交），禁止任何直接 push；合并锁定精确 head 后，服务器 cron 环境设 `HQ_DRIFT_EXCEPTIONS_REF=<合并后 baseline 精确 head SHA>` 锁定读取版本；未设 `HQ_DRIFT_EXCEPTIONS_REF` 时回落到 `GIT_REF`（即 `origin/baseline/test-server` 最新）
- 定时任务：`/etc/cron.d/huangque-drift`，每小时 17 分 `--print` 记录（当前不告警）。**告警切换方式：确认 `--print` 输出 `registered 58` 与例外清单对账一致后，去掉 cron 命令中的 `--print` 即恢复飞书告警（带 6 小时冷却）**
